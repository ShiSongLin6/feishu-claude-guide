# 国内版飞书接入 Claude 桌面应用：经验与工具

一次踩坑后的总结：在个人（豆包）账号下**手工建飞书应用 + lark-mcp** 授权一直失败（"无法授予的权限""当前账号无法使用"），改用官方 **`lark-cli` + 官方 skill** 后走通。

## 内容
| 路径 | 说明 |
|---|---|
| `skills/debug-integration-setup/` | 通用的"接入服务卡住时怎么想"：先找已有的、让报错说话、分清沙箱与本机。可作为 Claude skill 使用。 |
| `skills/feishu-cn-lark-cli-setup/` | 国内版飞书的具体步骤与注意事项。 |
| `scripts/` | Windows 双击脚本：没有 Git 时，把打包好的官方 skill 解压到 `~/.claude/skills`。 |

## 关键结论
1. 手工应用在个人账号下可能卡在授权，补权限、发版本都没用；官方 `lark-cli` 的一键注册应用可以。
2. skill 里的命令要在**你电脑上直接执行**。聊天/协作沙箱是 Linux 虚拟机，碰不到你的 `lark-cli`，请用 **Code 模式的本地会话**（选你电脑上的文件夹，不要选云端）。
3. `~/.claude` 是 Claude 的保护目录，助手写不进去，最后一步要自己双击脚本。

## 状态说明（请如实阅读）
- **推荐路径：Code 模式（本地会话）。** 官方 `lark-cli` 登录、官方 skill 安装都已在作者电脑上验证；skill 让 Claude 直接在本机运行 `lark-cli`，不需要任何桥接。
- **试过但没成功：** 写一个本地小 MCP，把聊天模式的请求转给 `lark-cli`。作者在实际使用中验证后认为不可行（配置没有稳定生效），因此本仓库**不提供**这部分代码。要用飞书，请直接用 Code 模式。
- `config init` / `auth login --recommend` 来自第三方教程，作者本人因机器上已有登录而未亲自执行。
